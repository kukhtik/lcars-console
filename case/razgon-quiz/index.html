Problem

A quiz night is a live show: a projector in the hall, a host steering from a phone, teams answering, and a scoreboard that must be right in front of a paying audience. Off-the-shelf quiz apps assume every player has a stable connection and that the host can fix the score by hand — neither survives a real venue with bad Wi-Fi.

Approach

A single server owns the state and the score. The hall screen opens by a tokenised link (a plain game URL cannot control the show), one click unlocks the browser's AudioContext, and the host pages through questions with a keypress while each question's "fuse" timer runs itself. Because the hall answers on paper and only the host types, the server never has to hold hundreds of player sockets — the venue keeps working on a poor connection. The front end is a PWA with explicit precache (386 entries); every one of the 98 mp3 cues is cached by name, because a missed track is silence without an error. Hall — question with a 30-second fuse timer and live answer/accuracy stats Scoreboard — the server scores it; places, round points, game points Host remote — controls the show from a phone Player — joins by game code, answers, sees points Builder — rounds, questions, per-question music and timing
